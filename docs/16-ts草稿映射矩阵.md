# 16 · ts 草稿映射矩阵（正向 ts 全键 ← 原料 + 处理方式）

> 读者：analyzer 侧维护会话 + 消费方联调对账。本表是 ts 草稿投影（`ts_export`，波 B）
> 的**实施合同**：对齐靶 = 正向设计链路真实产出 `vendor/ts_draft/ts_sample_forward.json`
> （全貌），进门验 = `ts_draft_v2.schema.json`（必填面）。每个槽位标注处理方式，
> 消费方联调时按本表逐键对账。
>
> **定位**：ts 草稿 = `ViewContext`（v1.7 收敛的三视图公共取数层）的 JSON 渲染，
> 与 tech_design.md **同源同口径**——它不是从 asset_facts 二次装配（那是信息损耗的
> 源头），而是从 knowledge 富表示直接还原。长期 tech_design.md 改由 ts.json 渲染。

## 处理方式标注

| 标 | 含义 | 纪律 |
|---|---|---|
| **R** 恢复 | 制品显式记载的设计结果，确定性还原进本体 | 12 章 §11.1 恢复声明进本体 |
| **D** 派生 | 由既有事实确定性派生（拓扑角色、计数、分桶） | 文法/结构推导，非语义 |
| **E** 留空 | 判断位/设计语义，制品从未显式表达 → 合法空结构 | §11.2 推断不冒充声明 |
| **P** 带源回填 | 显式痕迹可回填本体，须同步 `_reverse.evidence` 带 provenance | §11.2（dq_pk_check / merge_on） |
| **N** 不产 | 不属逆向草稿范畴 | design / init / dq_rules |

## 一、顶层

| 键 | 标 | 原料 / 规则 |
|---|---|---|

## 二、meta

| 键 | 标 | 原料 / 规则 |
|---|---|---|
| target.f_table {schema, table, cn} | R | engine_ctx final_target + catalog `__table_comment__`（DDL 表注释） |
| target.i_view {schema, table, cn} | R / E | yml 场景 `asset_info`（I 视图发现）；facts 目录通道 DDL 仅解析 CREATE TABLE → 空结构 + 披露（**缺口 1**：CREATE VIEW 识别待补） |
| dq_required | R | DQ 检出=1 / 未检出=0（事实计数，"检出啥就是啥"） |
| grain | E | `""` |
| business_key | E → P | `[]`；dq_pk_check 识别口径定稿后可回填带 provenance（后续） |
| load_strategy {strategy, label, delete_mode} | R | 引擎 meta.load_strategy（**本仓标准枚举**——用户决策：消费方遵循本仓枚举） |
| field_count {business, audit, total} | D | 目标表字段计数；audit = 实际存在的标准审计列数（不补造） |
| source_tables [{schema, table, table_cn, alias}] | R | `ViewContext.entity_source_tables()`（EntitySource.alias=SQL 实际别名）+ catalog 表注释 |
| schedule.schedule_type / cron | R | `schedule_recovery.recover_schedule`：cron ← F 任务调度周期；type ← cron 频率确定性推断 |
| schedule.exec_params | R | GroupVariables → {名: {value_type:"", desc:"", default_value}}（类型/描述制品无 → 空） |
| schedule.lts_params | R | taskParams → [{lts_var, etl_param(${P_xxx} 提取), desc:""}] |
| schedule.tasks.f / view / dq | R | F/I/DQ 任务 → {task_name, job_name(主 job), cron, upstream, project_name, task_group, depends_prev_cycle} |
| schedule.tasks.*.upstream[] | R / E | tskdep 型 job → {task, table, project, group}（按主 job 名↔任务名匹配；未匹配 resolved=false 不编造）；**dep_type 留默认"宽依赖"**（制品无依赖语义类型——E）；`depends_prev_cycle` 为自依赖开关随行，不冒充 dep_type |
| schedule.upstream_added | R | = tasks.f.upstream（资产主调度的上游） |

## 三、tables（短表名 → 结构；仅规则产出表，源表进 meta.source_tables）

| 键 | 标 | 原料 / 规则 |
|---|---|---|
| type | D | 拓扑角色：被其他规则读 → intermediate，否则 target |
| business_key | E | `[]` |
| distribution_key | R | catalog fields `is_distribute_key` 列 |
| distribute_type | R / D | table_props.distribute_by 首 token（HASH/REPLICATION/ROUNDROBIN）；无子句且无分布列 → `ROUNDROBIN` |

| storage | R | table_props.with_options 的 orientation（column/row）；无 → `""`（**不硬编码 column**） |
| logical_group | R | DDL `TO GROUP xxx` 子句（**缺口 2**：`_extract_table_props` 待补抽 to_group；补前 `""`） |
| build_mode | E | `""` |
| fields [{target_field, field_type, field_comment}] | R | catalog ∪ 血缘字段名（**三键纯元数据**——两视图分界，加工语义不在此；用户决策 1） |
