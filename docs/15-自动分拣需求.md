# 15 · 制品类型自动分拣需求（消费方增量需求，2026-10-14）

> 来源：design-dev-agent 侧维护者反馈（经用户转达的诉求："每次指认太麻烦，系统能不能自己查"）。
> 本文自包含——不需要读消费方仓任何文件。背景：编排合入（`--manifest` 模式）已双方实施，
> 当前 manifest 的 `artifacts` 段要求**人指认**每个 excel 的类型（execution_tasks / lts / dq）。

---

## 一、需求：manifest 装配层按 sheet 结构指纹自动判型

**实测依据**（消费方在参考语材上验证）：三类平台 excel 的 sheet 指纹**完全不重叠**——

| 制品类型 | 必选 sheet 指纹（建议判定依据，你们可按解析器实际认知调整） |
|---------|--------------------------------------------------------|
| 术加制品包 | 含 `RULE` + `TargetFields`（固定 10-sheet 结构） |
| LTS 调度任务 | 含 `tasks` / `jobs` / `taskParams` |
| DQ 制品 | 含 `规则基础信息`（主 sheet） |

**需求形态**：

1. `artifacts.execution_tasks / lts / dq` 三键支持收**目录或文件组**（如
   `{"excel_dir": "/path/to/制品目录"}` 或数组）——装配层读 sheet 指纹分型后走既有通道；
2. **判不了 / 多义 / 结构不符 → fail loud**，报"无法识别的文件 X（缺 Y sheet）"——不猜；
3. **显式指认通道保留**（现状 `execution_tasks: <path>` 形态不变，优先级高于自动分拣）——
   指认了就按指认走，指认错仍由资产强校验拦；
4. **DQ"无"仍需显式**：自动分拣发现得了"有"、发现不了"无"（无文件 ≠ 无 DQ，三态语义
   不变）——`dq: {"status": "declared_absent"}` 声明通道照旧，沉默仍违规；
5. 资产强校验（制品解析目标表 vs `asset.table`）不变——分拣错误导致的串包仍被这道拦住。

## 二、验收标准（建议）

1. 三类参考语料 + 干扰文件（非 excel / 缺 sheet 的 excel）混一个目录 → 分型正确、
   干扰文件报"无法识别"；
2. 同目录两个同型 excel（多义）→ fail loud 报多义，不静默取其一；
3. 显式指认 + 目录混给 → 指认优先、目录分拣其余；
4. `declared_absent` + 目录里恰有 DQ 形态文件 → fail loud（声明与发现矛盾）；
5. 现有 manifest 测试全绿（显式通道零回归）。

## 三、边界重申

- 判型知识单源在你们（解析时本来就要认这些 sheet；消费方不实现第二份指纹逻辑）；
- 指纹判定依据若与你们解析器认知有出入，以你们为准调整 §一 表格并知会消费方同步文档；
- 本需求不涉及契约 schema 变更（baseline_v1 产物形态不变），只动 manifest 装配层。
