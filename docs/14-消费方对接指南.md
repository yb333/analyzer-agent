# 14 · 消费方对接指南：如何调用 dws-pipeline-analyzer 产出 baseline_v1

> 读者：design-dev-agent 侧（dws-reverser agent 开发 / 优化流程维护）。本文是**调用方视角**
> 的操作文档——怎么装、怎么调、怎么读产物、失败了怎么办。契约字段的权威口径见
> `docs/baseline_v1-契约.md`；己方实施设计见 `docs/13-v2支持方案与分层原则.md`。

---

## 一、总览：两种调用形态

| | 编排模式（推荐，v2 主路径） | 文件交接模式（兼容保留） |
|---|---|---|
| 入口 | `--manifest {manifest.json}` | `--input {xlsx或规则组目录}` + 各源参数 |
| 适用 | dws-reverser 编排起调（excel 制品场景） | 人工/流程直接给输入；yml 代码仓资产 |
| 输入 | 多制品一次收全（清单见 §三） | 术加 xlsx 或 yml 目录，LTS/DQ/DDL 各自选给 |
| 产物 | `manifest.output` 精确路径，**只交契约文件** | `{output}/{规则组英文名}/baseline_v1.json` |
| 失败 | fail loud，stderr 错误清单 = 交卷终态 | 同左（人工处理） |

**不变项**：起调的是 agent，不调任何内部脚本（入口只有 run.py）；契约始终以文件形态
落盘交接；一次调用一次交卷，流程不做反复调用。

## 二、安装与环境

```bash
# 安装（全局 ~/.config/opencode/skill/dws-pipeline-analyzer；--local 装项目 .opencode/skill/）
./install.sh            # macOS/Linux
install.bat             # Windows

# 环境要求：Python 3.10+；依赖 openpyxl / sqlglot / pyyaml（yml 场景）/ jsonschema>=4.0（契约导出）
# run.py 启动自检依赖，缺时友好提示；调用前可自查：
python -c "import openpyxl, sqlglot; print('OK')"
```

- **skill 安装名 = `dws-pipeline-analyzer`**（dws-reverser 的 skill 指针按 opencode 安装名
  解析，不按仓路径）
- 所有命令经 `run.py` 调度：`python {skill_dir}/run.py analyzer ...`（Windows 用 `python`，
  macOS/Linux 无 `python` 时用 `python3`）

## 三、编排模式（--manifest）

### 3.1 manifest 定义

dws-reverser 按任务 prompt 的三元组（制品路径清单 / 资产标识 / 输出落盘路径）生成。
两种写法：**逐键指认**（原形态）或 **excel_dir 混目录自动分拣**（docs/15——三类 excel
的 sheet 指纹不重叠，装配层自动判型，用户不用指认每个文件是什么）：

```json
// 写法一：逐键指认（原形态，继续支持）
{
  "asset": {"schema": "dws", "table": "dwb_cust_asset_d"},
  "artifacts": {
    "execution_tasks": "/abs/path/execution_tasks.xlsx",
    "lts": "/abs/path/schedule-tasks.xlsx",
    "dq": {"status": "provided", "path": "/abs/path/dq.xlsx"},
    "ddl": ["/abs/path/ddl_a.sql", "/abs/path/ddl_dir"]
  },
  "output": "/abs/path/workdir/baseline_v1.json",
  "platform_generation": "1.0"
}

// 写法二：excel_dir 混目录自动分拣（推荐——制品丢一个目录即可）
{
  "asset": {"schema": "dws", "table": "dwb_cust_asset_d"},
  "artifacts": {
    "excel_dir": "/abs/path/制品目录",
    "dq": {"status": "declared_absent"},
    "ddl": ["/abs/path/ddl_dir"]
  },
  "output": "/abs/path/workdir/baseline_v1.json"
}
```

**自动分拣规则**（`inputs.classify_artifact_excel`，判型知识单源在解析侧）：

| 制品类型 | sheet 指纹 |
|---|---|
| 术加制品包 | 含 `RULE` + `TargetFields` |
| LTS 调度任务 | 含 `tasks`（jobs/taskParams 为可选附属） |
| DQ 制品 | 含 `规则基本信息` |

- `excel_dir` 目录里每个文件必须可判型——非 excel / 缺指纹 sheet 的文件 fail loud
  （报"无法识别的文件 X（原因）"，错误一次报齐）；Excel 锁文件（`~$`）/ 隐藏文件 /
  子目录自动忽略
- 每型恰一个候选：同型多个 → 多义 fail loud，不静默取其一；术加缺失 → fail（必给）
- 各键也支持收**目录或文件组**（如 `"lts": "/abs/dir"` 或 `["a.xlsx"]`）——目录内
  只收该型，混入他型文件报错
- **显式指认优先于自动分拣**（指认了就按指认走，指认错由资产强校验拦；excel_dir
  另分拣到同型时 stdout 提示已忽略）
- **DQ"无"仍需显式**：分拣发现得了"有"、发现不了"无"——目录里没有 DQ 文件 ≠
  资产无 DQ，`declared_absent` 声明照旧必须；声明与发现矛盾（declared_absent +
  目录有 DQ 文件）→ fail loud
- `dq` 也可以直接给路径字符串（= provided + 自动定位）

| 字段 | 必填 | 说明 |
|---|---|---|
| `asset.table` | 是 | 资产标识；与制品解析出的最终目标表**强校验**（防串包） |
| `asset.schema` | 否 | 给了则参与一致性校验 |
| `artifacts.execution_tasks` | 是* | 术加制品包 excel（query_sql 唯一来源，无兜底）；*或经 `excel_dir` 分拣获得。值可为文件（显式）/ 目录 / 数组 |
| `artifacts.lts` | 否* | LTS 调度任务 excel（平台导出三 sheet）；**增量资产流程必给**（增量变量=回刷地基），全量可不填。缺省 → 契约 `schedule: null`。值可为文件/目录/数组 |
| `artifacts.dq` | 是 | **三态必须显式**（见下），缺 key 即违规 |
| `artifacts.ddl` | 否 | DDL 路径数组（文件/目录混合）；缺省 → `table_props: null` + 类型消费方查库回填（连库兜底通道在后续波次） |
| `artifacts.excel_dir` | 否* | 制品目录（自动分拣三类 excel，见上表指纹；*与 execution_tasks 至少其一） |
| `output` | 是 | 产物精确路径（父目录自动创建） |
| `platform_generation` | 否 | 默认 `"1.0"`；术加迁移 2.0 时传 `"2.0"`（write_plan 映射按代次换版） |

**DQ 三态**（"没有"和"忘了"必须可区分，沉默态在消费侧流程已拦，到这里必须显式）：

| status | 语义 | 契约产物 |
|---|---|---|
| `provided`（带 path） | 资产有 DQ，excel 给了 | `dq_rules: [...]`（规则列表） |
| `declared_absent` | 用户声明资产无 DQ | `dq_rules: []`（明确没有，**入档后永不再问**） |
| （缺 key） | — | **违规**，装配即 fail loud |

### 3.2 调用与产物

```bash
python {skill_dir}/run.py analyzer --manifest /abs/path/manifest.json
```

- 成功：exit 0；产物落 `manifest.output`；stdout 单独一行
  **`baseline_v1: {绝对路径}`**——agent 按该行前缀解析定位（manifest.output 已知，
  此行是双保险）。产物已过本仓权威 schema 全绿 + 语义校验（交卷即终态）。
- **编排模式只交契约文件**：draft/summary 等中间产物不落盘，产物目录只有
  baseline_v1.json。
- 与 `--input` 互斥；编排模式不需要 `--output`。

### 3.3 生成 manifest 前自查（装配层会拒绝什么）

| # | 违规 | 报错特征（stderr） |
|---|---|---|
| 1 | manifest 不存在 / JSON 非法 | `[manifest] 装配失败: ...` |
| 2 | `asset.table` / `output` 缺失 | 同上（字段名在信息里） |
| 3 | `execution_tasks` 缺失/文件不存在（或 excel_dir 分拣不到术加） | 同上 |
| 3b | excel_dir 目录里有无法判型的文件 / 同型多个（多义）/ dq 声明与发现矛盾 | `[manifest] 装配失败:` + 逐条清单（一次报齐） |
| 4 | `lts` 给了但文件不存在 | 同上 |
| 5 | `dq` 缺 key / status 非法 / provided 缺 path 或文件不存在 | 同上（提示三态写法） |
| 6 | `ddl` 数组元素路径不存在 | 同上 |
| 7 | provided 但 excel 无有效规则行（主 sheet「规则基本信息」无带规则Number的数据行） | `...无有效规则行...请核对 DQ 制品` |
| 8 | 制品解析目标表 ≠ `asset.table`（串包） | `[manifest] 资产不一致：制品解析目标表 = X，manifest.asset = Y` |
| 9 | 契约校验不过（如 dm=6 无 merge_on） | `[baseline_v1] 导出失败，产物未落盘：` + 违规清单 |

以上全部 **exit 非 0、产物不落盘**——错误清单原样退回，由消费侧流程决定补数动作
（编排模式无回问通道，§五的动作表由流程承接）。

## 四、文件交接模式（兼容保留）

```bash
# excel 制品
python run.py analyzer --input {术加.xlsx} --output ./output/ \
    [--lts {LTS excel}] [--dq {DQ excel}] [--ddl-dir {DDL目录}] \
    --export baseline_v1 [--platform-generation 1.0]

# 代码仓 yml 资产（LTS/DQ/DDL 自动发现）
python run.py analyzer --input {规则组目录} --output ./output/ --export baseline_v1
```

- 产物：`{output}/{规则组英文名}/baseline_v1.json` + stdout 定位行（同上）
- `--lts` / `--dq` 优先于代码仓自动发现；两源产出同构，契约形态不因源差异而变
- `--ddl-dir` 接收目录（xlsx 场景 DDL 不自动发现）
- yml 场景自动发现：DDL（仓结构定位）/ LTS（V_GROUP_CODE 匹配）/ DQ（目标表双确认）/
  I 视图（_f→_i 命名 + 兜底搜索）

## 五、失败语义与处理动作（fail loud 即终态）

| stderr 特征 | 原因 | 消费侧动作 |
|---|---|---|
| `[manifest] 装配失败: ...` | manifest 结构/路径问题 | 修 manifest 重新生成后再调 |
| `...无有效规则行...` | provided 但 DQ excel 空 | 核对 DQ 制品是否导出对/资产是否应走 declared_absent |
| `[manifest] 资产不一致：...` | 制品与资产标识串包 | 核对任务 prompt 的制品清单与资产标识 |
| `delete_mode=6 ... merge_on 为空` | 增量规则的合并 ON 配置缺失（制品删除条件列漏填） | 向用户/平台要该规则配置，补进源制品后重调 |
| `query_sql` 相关违规 | 源文件被截断/为空 | 检查术加制品完整性 |
| `[baseline_v1] 导出失败` + 清单 | 契约校验不过（其他） | 按清单逐条处理；**禁止**任何一方代填/编造后重跑 |

## 六、产物速览（当前 version = 1.2）

| 段 | 来源 | 消费要点 |
|---|---|---|
| `rules[]` | 术加制品（逐字保真） | query_sql/delete_condition 逐字节锚点，禁比对时归一 |
| `rules[].write_plan` | dm+条件结构化（v1.1） | kind 直接给写入类型，condition_columns 可直接做围栏 |
| `tables[].table_props` | DDL 表尾子句（v1.2） | 分布键/分区/存储参数原文，ts 投影再生物理事实来源；无 DDL = null |
| `tables[].fields[].is_distribute_key` | DDL 解析（v1.2） | 分布键变更=重分布成本，可做高严重度信号 |
| `schedule` | LTS excel / yml 发现 | jobs/params 事实原样；缺 = null |
| `dq_rules[]` | DQ excel / yml 发现（v1.2 含 target_schema） | `[]`=声明无，`null`=未提供 |
| `provenance[]` | 装配层采集 | xlsx 制品带 `sheets`（文件+sheet 定位，v1.2）；DDL 记清单原路径 |
| `warnings[]` | 交叉验证 | 报告+存档，不参与 patch 决策 |

完整规格与三级语义分级见契约文档 §四。

## 七、版本与同步协议（12 章 §六）

- 契约变更**本仓先行**（schema + 契约文档 + fixtures + version bump）→ 消费方跟随
  （re-vendor + `SUPPORTED_VERSIONS` + 消费端适配 + 契约测试绿）→ 同波各自同步内网。
- 当前权威版本 **1.2**（本仓支持读取 1.0/1.1/1.2）；vendor 同步步骤见契约文档
  §七「消费方同步指南（v1.1 → v1.2）」。
- 消费方同步工具的联锁检查（vendor 版本 vs 本仓 schema 版本不一致即拦截）由消费方实施。
- 双端契约测试各自维护，fixture 不跨仓 import。

## 八、FAQ

**Q：增量资产哪些制品必给？** 术加 + LTS 必给（schedule.params 是回刷地基）；DQ 按三态
显式；DDL 给则用、缺则 table_props=null（类型回填查库）。

**Q：yml 代码仓资产能用 manifest 吗？** 当前 manifest 只覆盖 excel 制品场景（v2 首优
一次的形态）；yml 资产走 §四文件交接模式。

**Q：制品里同时有多张表的规则？** manifest 的 execution_tasks 应是该资产的制品包；
解析出多步骤/多目标表时以最终目标表与 `asset` 校验，中间表按事实进 tables[]。

**Q：能只跑解析不出契约吗？** 可以——`--input` 不带 `--export` 走 /analyze 文档化路径
（draft + 三视图），与契约导出共用同一解析引擎。

**Q：制品文件名乱七八糟能分拣吗？** 能——判型只看 sheet 指纹（与文件名无关），
三类指纹不重叠；判不了会 fail loud 报具体文件与原因，不会猜。

**Q：DQ excel 的参数配置/输出列配置 sheet？** 需求未清晰暂不消费（对账表已登记去向）；
当前只消费主 sheet「规则基本信息」。扩充时由本仓按对账表 bump 契约。
