# 14 · 消费方使用说明：调用 facts 服务产出 asset_facts

> 读者：design-dev-agent 侧（dws-reverser agent 开发 / 优化流程维护）。本文是
> **facts 服务的完整调用合同**——怎么调、退出码/错误码什么含义、失败后做什么。
> 契约字段口径见 `docs/asset_facts-契约.md`（权威）。v1.3 起 `--manifest` 通道
> 已删除，本文只保留 facts 标准入口与 `--input` 人用形态。

---

## 一、服务概述

**你给**：一个制品目录 + 一个产物落盘路径。**你收**：一份过权威 schema 全绿的
asset_facts.json（存量资产物理事实包）。

- 制品类型识别**全在服务侧**：excel 按 sheet 结构指纹判型（术加=RULE+TargetFields /
  LTS=tasks / DQ=规则基本信息），`.sql`/`.ddl` 后缀即型归 DDL——调用方不指认、
  不构造任何中间结构（manifest 已删）
- 文件命名、目录组织、混放非制品文件（mapping/RS/说明文档）零要求：无法识别的
  文件不阻断，逐个进产物 `warnings`（type=`unrecognized_artifact`），你们的闸口
  人扫兜底
- **唯一硬闸**：术加制品包（含 RULE+TargetFields sheet 的 excel）缺失或判不出 →
  整体 fail（没有它无法产出）；同型制品多个（多义）→ fail 不静默取一

## 二、标准调用（唯一命令）

```bash
python {skill_dir}/run.py facts --dir <制品目录> --output <asset_facts.json 绝对路径>
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `--dir` | 是 | 制品目录（该资产全部原始制品；skill 安装名 `dws-pipeline-analyzer`） |
| `--output` | 是 | 产物落盘路径（父目录自动创建） |

## 三、退出码与输出约定（agent 分流依据）

| 退出码 | 含义 | stdout / stderr | 你该做什么 |
|---|---|---|---|
| **0** | 成功交卷 | stdout 单独一行 **`asset_facts: {产物绝对路径}`**（按行前缀解析定位）；产物已过权威 schema 全绿，交卷即终态 | 读定位行拿产物，进你们校验链（版本→schema→内部一致性→资产对账） |
| **1** | 制品/数据问题 | stderr 逐条**可行动**错误清单（哪个文件、什么问题、缺什么料）；产物不落盘 | 错误清单**原样上报流程**——据此向人要料或退回；不重试、不代填、不构造新输入绕过 |
| **2** | 调用参数错误（调用方问题） | argparse 报错 | 修正参数后重新调用 |

**stderr 错误特征 → 行动对照**：

| 错误特征 | 原因 | 行动 |
|---|---|---|
| `缺必需料：目录中未识别出术加制品包 excel` | 目录里没有含 RULE+TargetFields 的 excel | 向人要术加制品包（导出该资产的执行任务 excel） |
| `多义：[a.xlsx, b.xlsx]` | 同型制品多个 | 请人确认保留哪个（或分目录重调） |
| `DQ 制品无有效规则行` | 分拣出 DQ 形态但主 sheet 无规则数据行 | 核对 DQ 制品导出是否完整 |
| `[asset_facts] 导出失败` + 清单 | 契约校验不过（如 dm=6 无 merge_on） | 按清单向人要配置（如增量合并 ON），补进源制品后重调 |
| `制品目录不存在` | --dir 路径错 | 核对路径 |

## 四、产物速览（version = 1.3）

| 段 | 来源 | 消费要点 |
|---|---|---|
| `rules[]` | 术加制品（逐字保真） | query_sql/delete_condition 逐字节锚点，禁比对时归一 |
| `rules[].write_plan` | dm+条件结构化 | kind 直接给写入类型，condition_columns 可直接做围栏 |
| `tables[].table_props` / `fields[].is_distribute_key` | DDL 物理属性 | ts 投影再生的物理事实来源；分布键变更=重分布成本 |
| `schedule` | LTS excel / yml 发现 | jobs/params 事实原样；未检出 LTS=null + `lts_not_detected` warning |
| `dq_rules[]` | DQ excel / yml 发现 | **两态**：检出=列表（含 target_schema）；未检出=`[]` + `dq_not_detected` warning（闸口据此向人披露纠错） |
| `provenance[]` | 装配层采集 | xlsx 制品带 `sheets`（文件+sheet 定位）；DDL 记原路径 |
| `warnings[]` | 四源合流 | 含分拣披露（unrecognized_artifact / dq_not_detected / lts_not_detected）——报告+存档+闸口人扫 |

## 五、dws-reverser 岗位提示词模板（可直接嵌入）

以下模板即本服务的全部调用知识，贴进 agent 岗位定义即可，无需理解 analyzer 仓：

```
当任务需要逆向存量资产（产出 asset_facts 事实包）时，执行一次调用：

python {skill安装路径}/run.py facts --dir {制品目录} --output {产物绝对路径}

判定与动作：
- exit 0：从 stdout 找以 "asset_facts: " 开头的一行，取其后路径即产物（已过
  生产方权威 schema 校验）。一次调用一次交卷，不做第二次调用。
- exit 1：制品/数据问题。把 stderr 错误清单原样上报流程（要料/退回），
  禁止：重试、代填数据、自行修改制品、构造其他输入绕过。
- exit 2：参数错误。核对 --dir/--output 后重新调用一次。

不构造 manifest 或任何清单结构——制品类型由服务自动识别。
无法识别的文件不会阻断（会进产物 warnings），无需预先清理目录。
```

## 六、安装与环境

```bash
./install.sh            # 或 install.bat；--local 装项目级
# skill 安装名 = dws-pipeline-analyzer（岗位的 skill 指针按 opencode 安装名解析）
```

- Python 3.10+；依赖 openpyxl / sqlglot / pyyaml / jsonschema>=4.0（run.py 启动自检）
- 入口统一经 `run.py`（Windows 用 `python`，macOS/Linux 无 `python` 时用 `python3`）
- 运行环境依赖清单随 skill 走，消费方不代装包

## 七、面向人的备用形态（--input，非 agent 通道）

人工逐件指认或 yml 代码仓资产时使用；产物默认名 `asset_facts.json`：

```bash
python run.py analyzer --input {术加.xlsx 或 规则组目录} --output ./output/ \
    [--ddl-dir D] [--lts {LTS excel}] [--dq {DQ excel}] \
    --export asset_facts [--platform-generation 1.0]
```

yml 场景自动发现 DDL/LTS/DQ/I 视图；产物 `{output}/{规则组英文名}/asset_facts.json`。

## 八、版本与同步协议

- 契约变更**本仓先行**（schema + 契约文档 + fixtures + version bump）→ 消费方跟随
  （re-vendor + `SUPPORTED_VERSIONS` + 消费端适配 + 契约测试绿）→ 同波各自同步内网
- 当前权威版本 **1.3**（本仓读取兼容 1.0-1.2；产物只产 1.3）。v1.3 同步要点：
  1. vendor schema → `asset_facts.schema.json`（旧名文件已删，不留双名）
  2. `SUPPORTED_VERSIONS` 增加 `"1.3"`；产物定位行前缀改解析 `asset_facts:`
  3. dq_rules 两态语义（`[]` = 目录未检出，配 dq_not_detected warning）
  4. 调用方式从 `--manifest` 切到 `facts --dir/--output`（manifest 已删）
- 消费方联锁检查（vendor 版本 vs 本仓 schema 版本）由消费方实施

## 九、FAQ

**Q：增量资产哪些制品该在目录里？** 术加 + LTS（增量变量=回刷地基；缺 LTS 会产
`lts_not_detected` warning 披露，不阻断）；DQ 有则放（未检出=[]+披露）；DDL
（.sql/.ddl）给则用，缺则 table_props=null、类型回填查库。

**Q：yml 代码仓资产能用 facts 入口吗？** 不能——facts 只收 excel/sql 制品目录；
yml 资产走 §七 --input 形态。

**Q：目录里混了 mapping/需求文档会失败吗？** 不会。无法识别的文件进产物
warnings（unrecognized_artifact），产出照常；只有术加判不出才整体失败。

**Q：能只跑解析不出契约吗？** 可以——`--input` 不带 `--export` 走 /analyze
文档化路径，与契约导出共用同一解析引擎。

**Q：`.txt` 的 DDL 收吗？** 不收（.txt 可能是说明文档，歧义后缀不猜）；DDL 请用
`.sql`/`.ddl` 后缀。
