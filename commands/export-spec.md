# /export-spec — 需求 SPEC 导出命令

把资产制品目录（术加制品包 + 可选 LTS/DDL）逆向解析后渲染为 **需求SPEC.xlsx**
（新模板五 sheet，列口径 = docs/17-SPEC列级映射矩阵.md）。这是**面向人的交付件**：
业务背景等人工位要人补完才算成品。

## 与 /export-facts 的区别

| | /export-facts | /export-spec |
|---|---|---|
| 产物 | asset_facts.json（给 agent 读的契约） | 需求SPEC.xlsx（给人读/补的交付件） |
| 消费方 | design-dev-agent 等机器 | 需求/评审流程中的人 |
| AI 角色 | 零参与 | 跑命令+引导交互；**人工位禁止代填** |
| 输入 | 制品目录 | 制品目录（同一套指纹分拣，DQ 忽略） |

两者共用同一条装配/解析链（pipeline_core），口径同源。

## 用法

```
/export-spec {制品目录}
/export-spec @execution_tasks.xlsx     # 单文件也可，同目录的 LTS/DDL 会被自动识别
```

底层命令（agent 直调合同，人可不管）：

```bash
python {skill_dir}/run.py spec --dir {制品目录} [--output {路径}] [--scenario {场景}]
```

退出码：0=交卷 / 1=制品问题 / 2=参数错误；stdout 定位行 `spec: {绝对路径}` +
`self_check: {verdict}`。`--output` 可省略（默认 `./output/需求SPEC-{规则组英文名}.xlsx`）。

## 工作流（agent 执行步骤）

1. **定位制品目录**：用户给目录或 @ 文件。目录里 excel 按 sheet 指纹自动识别
   （术加必需；LTS/DDL 可选），认不出的文件不阻断但会披露。
2. **首跑**：`run.py spec --dir {目录}`。
3. **场景门交互**：若 stderr 出现 `scenarios: P_CUR, P_HIS`（多场景资产，SPEC 按
   单场景产出）——**把场景清单原样列给用户让TA选**，带 `--scenario {用户选择}` 重跑。
   禁止 agent 替用户选。
4. **交付解读**（交卷后向用户报告）：
   - 产物路径（`spec:` 行）；
   - **已自动填**：数据源清单（源系统/源表/DDL中文说明/分布键主键/LTS调度匹配）、
     表关联（ON/限制/写入前/预处理贴码/主表链预处理五段式）、需求字段
     （穿透源表字段/直取加工判型/拆解式加工逻辑/资产表与字段中文名）；
   - **待人工补**：Sheet1 业务背景 7 列、Sheet4 资产设计参考列、Sheet2 调度应用列
     （LTS 制品无对应字段）；缺 LTS/DDL 时对应列留空并见备注；
   - **备注列的两态**要看：「LTS制品未提供」（没给→可补料重跑）≠
     「未匹配到本资产源表」（给了没配上→任务在清单尾部，人工核对）。
5. **self_check 三态解读**：`pass` 全绿 / `pass_with_noise` 有留空披露（看披露行
   决定是否补料重跑）/ `review` **谓词守恒告警**（渲染漏放行级条件，信息失真
   风险，必须人工比对 SQL 原文并反馈维护者）。
6. **补料重跑**：缺 DDL（中文说明/主键/字段中文名空）→ 建议用户把 DDL 文件
   （.sql/.ddl）放进制品目录重跑；缺 LTS（调度列空）→ 同理。重跑覆盖旧产物。

## 失败分流（exit 1，AI 原样上报 + 引导，禁止自行编造）

| stderr 特征 | 人回路动作 |
|---|---|
| `多场景资产检测到 ... scenarios:` | 列场景给用户选，`--scenario` 重跑 |
| `场景 xxx 不存在；可选:` | 用户选错了，重新选 |
| `装配失败` / `缺必需料` / `多义` | 制品目录问题：确认术加 excel（RULE+TargetFields sheet）；同型多份只留一份 |
| `模板列头指纹不符` | 模板被改过——对照 docs/17 §八 流程恢复基准 |
| `谓词守恒`（review 态披露） | 渲染漏放谓词，人工比对 SQL 后反馈维护者修渲染层 |

## 关键规则

1. **零编造**：静态分析拿不到的列一律留空+披露（库类型//数据库前缀、主键唯一性
   等沿 154c435 纪律）；拆不出的逻辑贴 SQL 原文。
2. **人工位禁止 AI 代填**：业务背景/使用场景/需求价值等业务语义列，AI 补写=
   假信息风险，留给需求流程的人。
3. **场景选择权在用户**：agent 只转述清单不代选。
4. 命令幂等：同目录重跑覆盖旧产物；LTS 匹配标注（精确/模糊+分值）写进备注列
   供人工核对，模糊命中不保证正确。
